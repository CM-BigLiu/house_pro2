## 二、新发现问题

### 🟠 P1-1 · 审批流查询接口 500（`+entityId` 产生 NaN）

`GET /api/system/approvals`（不带 entityId）返回 500，后端报错：
`error: invalid input syntax for type integer: "NaN"`

**根因**：`approval.controller.ts:47-52`：
```ts
async findByEntity(@Query('entityType') entityType, @Query('entityId') entityId: string) {
  return this.approvalService.findByEntity(entityType, +entityId); // entityId 未传时 +undefined = NaN
}
```
与历史 `follow-up.controller` 的 `+bizId → NaN` 同一类 bug。

**修复**：
```ts
async findByEntity(@Query('entityType') entityType: string, @Query('entityId') entityId: string) {
  const id = Number(entityId);
  return this.approvalService.findByEntity(
    entityType || undefined,
    Number.isFinite(id) ? id : undefined,
  );
}
```
并在 `approval.service.findByEntity` 里对 `entityType/entityId` 做动态 `where`（值为 undefined 时跳过该条件），使不带参时返回全部记录而非报错。

### 🟠 P1-2 · WebSocket 依赖版本不匹配（ping/pong 无响应）

实测：`/events` 能握手连接（鉴权通过），但 `emit('ping')` 后**收不到 `pong` 且连接随即断开**。

**根因**：后端 `package.json` 混装了跨大版本依赖：
- `@nestjs/common` = `^10.3.0`（NestJS 10）
- `@nestjs/websockets` = `^11.2.3`（NestJS 11）⚠️
- `@nestjs/platform-socket.io` = `^11.2.3`（NestJS 11）⚠️

NestJS 要求所有 `@nestjs/*` 包版本一致；`@SubscribeMessage` 在 10/11 的元数据反射机制不同，导致事件虽「subscribed」但分发不到 handler（连接成功、消息静默丢弃）。

**修复**：把两个 websocket 包降到与项目一致的 10.x：
```bash
cd code/server
npm install @nestjs/websockets@^10.3.0 @nestjs/platform-socket.io@^10.3.0
```
重新 `npm run build` 后重启，验证 `ping`→`pong` 与 `status:change`/`dashboard:update` 广播。
