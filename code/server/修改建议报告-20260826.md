## 二、新发现的问题（重点）

### 🔴 P0 · 前端未适配统一响应格式（浏览器点击测试暴露，阻塞全部前端）

**现象**：登录返回 201 后，`/api/auth/me` 返回 401，页面停在登录页；所有列表页数据为空。

**根因**：后端 `1df0296` 提交引入 `TransformInterceptor`，所有成功响应包装为 `{code, message, data}`；但前端 `code/web/src/utils/request.ts` 响应拦截器（第 24-32 行）未解包 `data` 字段：

```js
request.interceptors.response.use((response) => {
  const data = response.data;          // 这里是 {code, message, data}
  if (data && 'code' in data && data.code !== 0 && data.code !== 200) { ... }
  return data;                         // ❌ 返回整个包裹，应返回 data.data
});
```

**连锁影响**：
- `stores/user.ts:24` `setToken(res.token)` → `res.token` 为 undefined → `/api/auth/me` 带 `Bearer undefined` → 401
- 全部列表组件（`SaleView/RentView/BillView` 等 25+ 处）`res.list`/`res.total` 均为 undefined → 列表空

**修复**（`code/web/src/utils/request.ts` 响应拦截器，改动 1 处即可全局恢复）：

```js
request.interceptors.response.use(
  (response) => {
    const body = response.data;
    if (body && typeof body === 'object' && 'code' in body) {
      if (body.code !== 0 && body.code !== 200) {
        ElMessage.error(body.message || '请求失败');
        return Promise.reject(new Error(body.message || '请求失败'));
      }
      return body.data;   // ✅ 解包统一响应的 data 字段
    }
    return body;          // 兼容非统一格式（如文件流）
  },
  ...
);
```

### 🟠 P1 · 黑名单多维校验 name 参数未暴露

`blacklist.service.ts` 的 `check(mobile, idCard, name)` 已支持姓名模糊，但 `blacklist.controller.ts:82` 只接收 `@Query('mobile')` 和 `@Query('idCard')`，**漏了 `name`**。实测 `check?name=王老赖` 返回空。

**修复**：controller 增加 name 参数：

```ts
@Get('check')
async check(@Query('mobile') mobile?, @Query('idCard') idCard?, @Query('name') name?) {
  return this.blacklistService.check(mobile, idCard, name);
}
```

### 🟠 P1 · 黑名单 idCard 加密导致数据不一致 + 校验失效

数据库 `house_blacklist` 实际状态：id=1 王老赖 idCard 为**密文**（92 位 `enc:...`），id=2 李违约 idCard 为**明文**（18 位）。实测 `check?idCard=310101199001011111` 返回空（种子明文与库中密文不一致）。

**根因**：`encryptedTransformer` 加入后，被 touch 过的记录（id=1）加密存储，未 touch 的（id=2）保持明文，且 id=1 解密后与种子明文不一致（疑为旧数据或密钥变更）。

**修复建议**：
1. 统一重灌黑名单种子数据（`docker compose down -v` 后重新 seed，或写一次性迁移脚本重新加密明文记录）；
2. `blacklist.service.check` 改为按 mobile/name 走 SQL 查询（mobile 未加密可直接查），idCard 因加密无法 SQL 匹配，改为「先按 mobile 查，再对候选记录用 transformer 解密后的 idCard 比对」，避免全表内存遍历。

---

### 🟡 P2 · 黑名单存在脏数据

id=4 记录 `name` 为乱码 `����`、`reason: "test"`，系此前 API 测试通过 `POST` 创建时中文编码错误产生。建议清理，并排查黑名单新增接口的中文编码（如确认请求 `Content-Type` 与 body 编码）。

### 🟡 P2 · 审批流无查询接口

`ApprovalService.submit` 仅内部记录，`approval-record` 无 GET 查询接口，UI 无法查看审批记录。建议补 `GET /api/system/approvals?entityType=&entityId=` 分页查询，并接入系统管理页。
