## 列表成交与配置交互补充（2026-09-28）

- 租房列表支持直接成交，无需先创建约看；普通房源使用普租字段，托管房源使用承租字段。与约看成交共用房态锁定、合同快照、分期及业绩计算，不生成虚假的约看记录。
- 房管房列表新增编辑及委托成交入口。委托成交带入已有业主、租期、金额及最近生效委托资料，仍禁止租期重叠。编辑及详情使用 `source=property-management` 保留返回列表、面包屑和菜单高亮。
- 配置金额使用普通输入框，非负数字、最多两位小数，失焦补齐两位。奖励选择员工主键，后端按员工状态及当前数据范围校验并保存真实姓名；历史手填姓名仅在唯一匹配时预选，否则提示重新选择。
- 本月/下月金额按付款到期月份汇总各期未结余额，即分期金额减累计已结金额，不能等同于整期合同金额或当月租金。

## 明确采用的计算口径

- 合同月仍以合同起始日为每月锚点；完整合同月收一个月租金，免租后剩余天数及不足整月的租期按实际天数 × 月租 ÷ 30 折算，租期结束日计入租金。日租不提前舍入，每期合计保留两位小数。月付、季付、半年、年付等均生成独立分期计划，最长十年。
- 例如月租4000元、2026-09-28起租、季付且首年免租45天：首期为 `4000 × 16 ÷ 30 + 4000 = 6133.33` 元，已付6000元后未结133.33元。免租仍按日历天数确定日期，不把合同或付款日期改为每30天滚动。
- 五年免租填写天数（0–365），从各合同年度周年起点扣除；免租收益为当月业主原租金减免租后的应付租金。溢价为当月承租约定租金减业主原租金，空置时可能出现负溢价。正负收益分别绿色/红色，零溢价单独显示。
- 房管房计佣 =（免租收益 + 溢价 − 本月配置费用调整）× 绩效分成；提成 = 计佣 × 提成比例。配置金额修改只在修改月记差额，不挪走之前月份已记成本；配置提交本身不代表资金已支付。
- 普租/承租计佣 = 合同佣金 × 绩效分成；提成 = 计佣 × 提成比例。买卖录入/成交比例须合计100%，金额按分计算，舍入尾差归成交份额，避免分配金额超出原金额。
- 比例由业务人员按实际约定填写，绩效分成默认100%、提成比例默认0%，没有预设公司提成政策。员工编号使用现有员工主键补齐六位；手工买卖归属姓名在报送时保存快照。
- 月份收益是合同归属口径，不等于实收；现金余额只计算成功登记的实际流水。银行两个账户分别保存余额，银行卡切换不合并余额。
- 非公司数据范围仅展示授权范围内的现金变动，不把公司期初余额叠加到局部流水。房源委托/配置仍仅原录入人与公司管理员可操作，数据范围不会扩大业主资料权限。
- 财务提交保存当时快照，审核不会改动现金流水或再次记业绩。待审或已保存的同人同类同月不能重复报送；退回后允许重报。
- 身份资料及账户加密存储，响应继续执行脱敏；审计日志不保存明文身份证和收付款账号。

## 升级与验证

1. 在测试库备份并验证后升级，先关闭 `DB_SYNCHRONIZE`，不要先让开发自动同步创建新表后再运行同一迁移。
2. 在 `code/server` 对已经配置好的目标数据库运行 `npm run migration:run`，应用 `1790575200000-BusinessFinanceWorkflow`。迁移新增合同详情/类型及五张业务表，初始化五个现金账户，更新菜单名称；不会清空旧台账。不要在已有新业务数据时直接执行迁移回退，它会删除新业务表。
3. 重启正式 NestJS 服务和前端，重新登录刷新菜单/权限。旧 mock-server 不支持新接口。
4. 旧合同缺失的身份证、付款日、佣金、免租期无法从历史数据推断：没有自动伪造/补录；旧托管开关记录应先补登记委托，再走新的承租成交。旧独立财务台账保留，不作为新合同流水重复计入。
5. 测试命令：后端 `npm test -- --runInBand --testPathIgnorePatterns=/int/`；前端 `npm run test -- --maxWorkers=2 --minWorkers=1`；两端 `npm run build`。

### 30天折算口径更新（2026-09-28）

部署新代码后，先备份目标数据库，在 `code/server` 运行 `npm run recalculate:lease-plans` 预览旧计划差额，再运行 `npm run recalculate:lease-plans -- --apply` 更新。命令从 `.env` 加载目标库配置，无表结构变更；可重复运行，不会重复增加金额。

仅重算生效或解约待处理合同的未结清计划，保留已结清/已取消计划、实际收付款流水及已报送财务快照。执行时锁定计划并使用事务；若任何新金额低于已结金额，则整批停止，不会覆盖实付金额或自动生成退款。新合同及未报送业绩使用同一30天折算函数。
