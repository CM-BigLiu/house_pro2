## 仍存在的严重缺陷（深度测试发现）

### P0-1【仍然存在】越权写完全未拦截（PermissionGuard 形同虚设）

**实测**：
1. `salesman`（个人范围）`PUT /house/sale-properties/2` 把 agent01 的房源 salePrice 改成 1 → **HTTP 200，数据被改**
2. `readonly`（只读）`POST /house/customers` 创建客户 → **HTTP 201，记录已落库**
3. `readonly` `DELETE /house/blacklist/1` → **HTTP 200，把"王老赖"黑名单删了**
4. `salesman` `POST /system/roles` 创建系统角色 → **HTTP 201**

**根因**：`code/server/src/app.module.ts` 虽然全局注册了 `PermissionGuard`，但**所有 controller 方法都没有加 `@RequirePermission(...)` 装饰器**，PermissionGuard 读到 `required = undefined` 就直接放行。

证据（`code/server/src/common/guards/permission.guard.ts:20`）：
```ts
if (!required || required.length === 0) return true;  // 没标 @RequirePermission 就放行
```

而全工程 grep `@RequirePermission` 只在 `auth.controller.ts` 的登录方法出现（用于豁免）：

```
code/server/src/modules/auth/auth.controller.ts:29: @SetMetadata('permissions', [])
```

**修复建议**：
1. 给所有 controller 写接口加细粒度权限点：
   - `POST /house/sale-properties` → `@RequirePermission('house:sale:create')`
   - `PUT /house/sale-properties/:id` → `@RequirePermission('house:sale:update')`
   - `DELETE /house/blacklist/:id` → `@RequirePermission('house:blacklist:delete')`
   - `POST /system/roles` → `@RequirePermission('system:role:create')`
   - 等
2. 在 service 层补**数据范围校验**：PUT/DELETE 必须先 `findOne` 并 `applyDataScope` 校验记录归属
3. 在种子权限表 `sys_permission` 里补这些动作权限点（type='action'），并给 readonly 角色只分配 type='menu' 的权限

**验收影响**：验收.md 7.3 数据权限、9.4 角色授权流程均为 P0 项，**当前完全不通过**。

### P1 严重缺陷（仍存在）

#### P1-1 售房详情接口缺失

#### P1-2 跟进记录接口缺失
`GET /house/followups`、`/house/sale-properties/:id/followups` → 404。`house_followup` 表已建，无 controller。验收 6.4 跟进 SLA 是 P1 项。

#### P1-3 操作日志接口缺失
`/system/logs`、`/system/operation-logs` → 404。`sys_operation_log` 表已建，无 controller、无拦截器自动写入。验收 7.4 审计是 P0/P1 项。

#### P1-4 售房管理卡片字段全部渲染为相同值
实测截图显示 3 张卡片的面积、户型、装修字段都显示 "88.00 m²、2室1厅1卫、精装"，但数据库中 3 套房源的实际字段不同：
- id=1: 88m², 2室2厅, fine（精装）
- id=2: 88m², 2室1厅, fine
- id=3: 88m², 1室1厅, simple（简装）

**根因待查**：可能是 `SaleView.vue` 卡片渲染时 `:key` 绑定错误，或字段映射到了同一个示例值。需要打开 `code/web/src/views/house/SaleView.vue` 检查 `v-for` 和字段读取。

## P2 体验问题（仍存在）

### P2-1 房屋创建 DTO 必填字段过多
`POST /house/sale-properties` 强制要求约 15 个字段（code/layoutBalconies/orientation/decoration/elevator/sourceChannel/taxType/debt/certificateType/title 等）。与 4 步向导渐进式录入的设计冲突。

### P2-2 dashboard/todos 字段缺失
返回 `[{id, title, priority}]` 缺 `date` 字段（overdue 分支漏赋值），前端待办列表日期列空白。

### P2-3 储备房源/租房/黑名单 POST 报 500 而非 400
缺少必填字段时后端返回 500 而非 400，前端无法 toast 具体字段错误。

### P2-4 售房管理筛选项较少
实测截图显示筛选区只有"小区/房号/业主"关键字输入框和"状态"下拉。验收 3.2.2.2 要求：备用电话、验真剩余时间数值区间、完整朝向、来源多选、室/厅/卫/阳 4 个独立控件等。
