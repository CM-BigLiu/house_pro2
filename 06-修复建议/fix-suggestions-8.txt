## 剩余 P0 阻塞缺陷

### P0-1【新发现】4 个页面统一的"rows is not iterable"前端解构 bug

**实测**：所有 9 个账号访问以下 4 个页面均触发 `TypeError: rows is not iterable`，el-table 卡在 loading 状态。

| 页面 | 文件 | 错误代码 | 后端返回 |
|---|---|---|---|
| 账单 | `code/web/src/views/finance/BillView.vue:26` | `list.value = await getBills(query);` | `{list, total}` |
| 流水账 | `code/web/src/views/finance/FlowView.vue:25` | `list.value = await getFlows(query);` | `{list, total}` |
| 欠款统计 | `code/web/src/views/finance/ArrearsView.vue:25` | `list.value = await getArrears(query);` | `{list, total}` |
| 人员管理 | `code/web/src/views/system/EmployeeView.vue:26` | `employees.value = await getEmployees(query);` | `{list, total}` |

**根因**：前端把 axios 返回值当数组用，但后端实际返回 `{list, total}` 分页对象。

**对比**：其他业务页面（售房/租房/储备房源/储备客源/黑名单/小区/合伙人/收支计划/涨价统计/公寓利润/收入成本/业绩核算/财务核算）已正确写 `list.value = res.list;`，只有这 4 个页面漏改。

**修复建议**（统一模式，改 4 处）：
```ts
// BillView.vue:26 改为：
const res = await getBills(query);
list.value = res.list || [];
total.value = res.total || 0;

// FlowView.vue:25、ArrearsView.vue:25 同理
// EmployeeView.vue:26 改为：
const res = await getEmployees(query);
employees.value = res.list || [];
total.value = res.total || 0;
```

**影响范围**：验收.md 3.3.1 账单、3.3.2 流水账、3.3.9 欠款统计、3.4.4 人员管理均为 P0/P1 验收项，**这 4 个页面目前完全无法显示数据**。

### P0-2【仍未修】客户管理店长查询 500

**实测**：仅 `store_manager` 账号在客户管理页触发：
- `GET /api/house/customers?keyword=&identity=` → **500**

其他 8 个账号（super_admin / boss / salesman / finance / housekeeper / agent01 / agent02 / readonly）调用同接口都返回 200。

**根因**（v5/v6/v7 已多次记录）：
- `code/server/src/modules/house/services/customer.service.ts:19` 调用 `applyDataScope(qb, user, 'c', { ownerField: 'creatorId' })`
- 对 `dataScope=store` 的角色会拼 `c.store_id IN (...)`
- 但 `code/server/src/modules/house/entities/customer.entity.ts` **没有 `store_id` 字段**

**修复建议**（选一）：
- A. 给 `house_customer` 表加 `store_id` 列（迁移脚本 + 创建时回填）
- B. `applyDataScope` 对 customer 走 `salesman_id → sys_employee_store` 关联子查询
- C. 简化：客户的数据范围改为"creator 所属门店"而不是"customer.store_id"

**验收影响**：验收.md 3.2.5 客户管理是 P0 验收项。

### P1-4 前端字典 API 路径与后端不一致
- 前端 `code/web/src/api/system.ts` 调 `/dictionaries`、`/dictionaries/:code/items`、`/dictionary-items`
- 后端 `code/server/src/modules/system/controllers/dict.controller.ts` 在 `/system/dicts`
- **但本次测试中，所有业务页字典调用 `/api/dictionaries/.../items` 都没在错误日志里** → 说明前端可能在某处做了路径映射或代理。

**待用户验证**：字典管理页 `/system/dictionary` 实际是否能加载？（本次测试显示 9 个账号都"完美"，可能是因为页面只渲染了空表格骨架，未实际触发字典接口）

### P1-5 售房卡片字段全部渲染为相同值
**实测**：super_admin 售房管理页 3 张卡片的面积、户型、装修字段都显示 "88.00 m²、2室1厅1卫、精装"——但数据库中 3 套房源实际面积、户型、装修不同。

**根因待查**：可能是 `SaleView.vue` 渲染时取错字段，或卡片使用了同一个固定示例值。需要打开 `code/web/src/views/house/SaleView.vue` 检查 `:key` 绑定和字段映射。

## P2 体验问题

### P2-1 房屋创建 DTO 必填字段过多
`POST /house/sale-properties` 强制要求 `code / layoutBalconies / orientation / decoration / elevator / sourceChannel / taxType / debt / certificateType / title` 约 15 个字段。与 4 步向导渐进式录入的设计冲突。

### P2-2 dashboard/todos 字段缺失
返回 `[{id, title, priority}]` 缺 `date` 字段（overdue 分支漏赋值）。

### P2-3 储备房源/租房/黑名单 POST 报 500 而非 400
缺少必填字段时后端返回 500 而非 400，前端无法 toast 具体字段错误。

### P2-4 售房管理筛选项较少
实测截图显示筛选区只有"小区/房号/业主"关键字输入框和"状态"下拉。验收 3.2.2.2 要求：备用电话、验真剩余时间数值区间、完整朝向、来源多选、室/厅/卫/阳 4 个独立控件等。
