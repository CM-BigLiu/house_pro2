## 本次新发现的 P0 阻塞缺陷

### P0-1【新】登录接口被全局 JwtAuthGuard 拦截，系统无法登录

**实测**：
- 打开 `http://localhost:5173/login`，输入 `super_admin / 123456`，点击登录
- `POST /api/auth/login` → **403 "缺少 Token"**
- 用户被卡在登录页，无法进入系统
- 错误密码也是 403（应区分 401 密码错 vs 403 缺 token）

**根因**：`code/server/src/app.module.ts:25` 把 `JwtAuthGuard` 注册为全局 `APP_GUARD`，但 `code/server/src/common/guards/jwt-auth.guard.ts` 没有 `@Public()` 豁免机制，登录、注册等公开接口全部被拦截。

**证据**：
```ts
// code/server/src/common/guards/jwt-auth.guard.ts:19
if (!token) throw new ForbiddenException('缺少 Token');
// 整个文件没有 Reflector / @Public / isPublic 判断
```

**修复建议**（参照 NestJS 官方 RBAC 教程）：
1. 新增 `code/server/src/common/decorators/public.decorator.ts`：
   ```ts
   import { SetMetadata } from '@nestjs/common';
   export const IS_PUBLIC_KEY = 'isPublic';
   export const Public = () => SetMetadata(IS_PUBLIC_KEY, true);
   ```
2. 在 `JwtAuthGuard.canActivate` 开头加：
   ```ts
   const isPublic = this.reflector.getAllAndOverride<boolean>(IS_PUBLIC_KEY, [
     context.getHandler(), context.getClass(),
   ]);
   if (isPublic) return true;
   ```
3. `JwtAuthGuard` 构造函数注入 `private reflector: Reflector`
4. 在 `AuthController.login` 上加 `@Public()` 装饰器（替换现有 `@SetMetadata('permissions', [])`）

### P0-2【新】vue-router 路由守卫逻辑错误，刷新任何子页面都跳到首页

**实测**：Playwright 注入有效 token 后 `page.goto('/house/sale')`，地址栏最终停在 `/home`。
**所有 25 个路由全部表现一致**：dashboard 200 → menus 200 → 然后跳到 /home。

**根因**：`code/web/src/router/index.ts:52-62`
```ts
if (!dynamicAdded) {
  const perms = userStore.permissions;
  const accessible = asyncRoutes.filter(...);
  accessible.forEach((route) => router.addRoute(route));
  dynamicAdded = true;
  return next({ ...to, replace: true });  // ← 这里 to 已丢失原 path
}
```

**问题分析**：在 `await userStore.fetchUserInfo()` 完成后，`to` 对象虽然保留了原 path，但 `next({...to, replace: true})` 是触发**第二次守卫调用**，此时 `dynamicAdded=true`，应直接 `next()`。但实际行为是：第一次 `next({...to})` 用 replace 替换历史，导致浏览器把 `/house/sale` 替换为 `/home`。

**修复建议**：
- 把 `return next({ ...to, replace: true })` 改为 `return next(to.fullPath)` 或 `return next({ path: to.path, query: to.query, replace: true })`
- 或在 `next()` 前 `await router.isReady()`，确保动态路由已生效
- 最佳做法：在 `fetchUserInfo` 完成后立即 `addRoute`，然后 `next(to.fullPath)`（仅传字符串路径，让 vue-router 重新匹配）

### P0-3【仍存在】首页看板 `/api/dashboard/rankings` 500

**实测**：9 个账号登录后访问首页均触发：
- `GET /api/dashboard/rankings` → 500
- 同时伴随 `Uncaught (in promise) Request failed with status code 500`，导致 HomeView 在 mounted 抛错

**根因**（v5/v6 已记录）：`dashboard.service.ts:198` 原生 SQL 用了 `created_at`，但 PostgreSQL 实际列名是 `createdAt`。

**附：`/api/dashboard/overview` 本次返回 200**（v6 时是 500），说明 14:24 的构建已部分修复 `getOverview` 的 `applyDataScope` 误用问题。但 rankings 仍在 500。

`/system/logs`、`/system/operation-logs` 均 404。实体 `sys_operation_log` 已建表，无 controller、无拦截器自动写入。

### P1-4 客户管理店长查询 500
`store_manager` 查询 `/house/customers` 500。根因：`Customer` 实体缺 `store_id` 字段，`applyDataScope` 对 store 范围角色拼 `c.store_id IN (...)` 报错。

### P1-5 登录失败无用户提示
错误密码登录，前端只看到 toast"没有权限执行该操作"（403 触发的 axios 拦截器提示），但实际上是用户名密码错。应区分：
- 401 → "账号或密码错误"
- 403 → "没有权限" / "登录已过期"

## P2 体验问题（仍存在）

### P2-1 未授权返回 403 而非 401
HTTP 语义错误。前端 axios 拦截器通常以 401 触发跳登录，403 被当作"已登录但无权限"。

### P2-2 储备房源/租房/黑名单 POST 报 500 而非 400
缺少必填字段时后端返回 500，前端无法 toast 出具体字段错误。

### P2-3 dashboard/todos 字段缺失
返回 `[{id, title, priority}]` 缺 `date` 字段（overdue 分支漏赋值）。

### P2-4 小区管理前端 `rows is not iterable`
前端 `CommunityView.vue` 期望 `Community[]`，后端返回 `{list, total}`，需要前端 `res.list` / `res.total` 解构。
