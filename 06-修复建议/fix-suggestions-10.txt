二、本次测试中发现并已直接修复的 Bug（2 个）
========================================================================

【修复-1】P0 后端启动崩溃（DI 依赖注入失败）
- 现象：`node dist/main` 启动即报错
  `Nest can't resolve dependencies of the OperationLogService (?).
   Please make sure that the argument "OperationLogRepository" at index [0]
   is available in the HouseModule context.`
- 根因：`src/modules/house/house.module.ts` 中 `OperationLogService` 注入了
  `OperationLog` 实体仓库，但 `TypeOrmModule.forFeature([...])` 未注册该实体。
- 修复：
  1) house.module.ts 增加 `import { OperationLog } from '../system/entities/operation-log.entity';`
     并加入 forFeature 数组。
  2) 同步把 house.module.ts 与 operation-log.service.ts 中错误的相对路径
     `../../system/entities/operation-log.entity` 改为 `../system/entities/operation-log.entity`
     （house 模块在 src/modules/house 下，上两级是 src/ 而非 src/modules/，导致 TS 解析失败）。
- 影响文件：
  code/server/src/modules/house/house.module.ts
  code/server/src/modules/house/services/operation-log.service.ts

【修复-2】P1 跟进列表 GET /api/house/follow-ups 500
- 现象：不带 bizType/bizId 查询时报
  `QueryFailedError: invalid input syntax for type integer: "NaN"`
- 根因：`follow-up.controller.ts` 直接 `+bizId`，bizId 为 undefined 时得 NaN 传入 SQL。
- 修复：controller 增加 `Number.isFinite(id)` 校验，非法时返回空数组。
- 影响文件：code/server/src/modules/house/controllers/follow-up.controller.ts

三、新发现的 Bug 清单（需修复）
========================================================================

【Bug-1】P1 · 账单列表字段全部显示「-」（前端字段映射错误）
- 位置：/finance/bill（BillView.vue）
- 现象：账单标题、款项种类、房源、租客、状态 5 列全部显示「-」，仅金额/到期日正常。
- 根因：前端绑定字段与后端返回字段名不一致——
  前端使用：title / category / houseTitle / tenantName / status('pending')
  后端返回：billSource / payer / payee / status('pending_receive')
  且前端 statusLabelMap 用的是 pending/paid/partial，与后端 pending_receive/received/overdue 不匹配。
- 后端实际数据（已验证）：
  id=1 陈租客 rent 3200 pending_receive 2026-08-29
  id=2 未知租客 rent 2200 pending_receive 2026-08-14
  id=3 张业主 commission 68000 received 2026-08-19
- 建议：BillView.vue 改用 payer/billSource/roomCode 渲染；status 映射改为
  { pending_receive:'待收', received:'已收', overdue:'逾期', cancelled:'作废' }；
  状态字典建议由后端字典 billing_status 统一下发。

【Bug-2】P1 · 售房卡片「总价」显示「-」（前端字段映射错误）
- 位置：/house/sale（SaleView.vue 第 121 行）
- 现象：卡片中「总价」一行显示「-」，单价/面积正常。
- 根因：前端绑定 `item.totalPrice`，后端返回字段是 `salePrice`。
- 后端数据：salePrice=7200000/5500000/6800000，unitPrice/buildingArea 正常。
- 建议：SaleView.vue 把总价改为 `formatMoney(item.salePrice)`；或后端序列化时补一个 totalPrice 别名，二选一统一。

【Bug-3】P1 · 租房卡片「月租 / 押金 / 房间数」显示「-」（前端字段映射错误 + 后端聚合缺失）
- 位置：/house/rent（RentView.vue 第 118/122/126 行）
- 现象：月租、押金、房间 3 项显示「-」。
- 根因：前端绑定 item.rent / item.deposit / item.roomCount / item.vacantCount，
  后端返回的租房套是 landlordRent + rooms[] 数组，没有 rent/deposit/roomCount/vacantCount 字段。
- 后端数据：landlordRent=9000，rooms[3]（A 租 3200 已租 / B 2600 空置 / C 已定）。
- 建议（二选一）：
  a) 后端 RentalSet 列表序列化时补 roomCount=rooms.length、vacantCount=rooms.filter(status==='vacant').length、
     rent=min(rooms.rentPrice)（或 landlordRent）、deposit=sum(rooms.depositAmount)；
  b) 前端改为读取 item.landlordRent 并从 item.rooms 聚合。
  推荐 (a)，保持前端简单。

【Bug-4】P0 · 非超级管理员角色被赋予全部系统管理权限（权限模型缺陷）
- 位置：登录 JWT / 侧边栏
- 现象：agent02（综合经纪人，数据范围 self）登录后，侧边栏可见「系统管理」一级菜单，
  JWT permissions 中包含 system、system:role、system:permission、system:dictionary、system:employee 等全部权限。
- 根因：code/server/src/database/seeds/seed.service.ts `seedRoles()` 第 146 行：
  除 super_admin 与 readonly 外，所有角色统一 `rolePerms = allPerms.filter(p => p.type==='menu' || p.type==='action')`，
  等于把全部菜单+操作权限都给了 salesman/agent/store_manager/housekeeper/finance 等角色。
- 与产品文档冲突：产品文档-最终.md 3.2 菜单权限矩阵明确
  系统管理仅 super_admin / company_admin 可见；财务管理仅 finance_* 与 store_manager。
- 建议：seedRoles 按角色分别配置权限码白名单，例如
  agent:  ['home','house','house:rent','house:sale','house:reserve_house','house:reserve_client','house:customer','house:blacklist','house:community']
  finance:['home','finance','finance:bill','finance:flow',...]
  salesman/store_manager 同理按 PRD 3.2 表逐项勾选。

【Bug-5】P1 · readonly 账号售房/租房列表为 0（assigned 数据范围未实现）
- 位置：/house/sale（readonly 登录）
- 现象：readonly（孙只读）登录后售房列表 Total 0。
- 根因：data-scope.util.ts 中 `assigned` 分支被简化为等同 store/self，
  且 Role.assignedStores 字段存在但未被读取注入 JWT。
- 与产品文档冲突：测试账号说明中 readonly 数据范围为「指定（当前简化）」，
  但 PRD 7.1/2.3 要求 assigned 应能指定具体店面列表。
- 建议：实现 Role.assignedStores 读取并注入 JWT payload.storeIds；
  data-scope.util.ts 按 storeIds 过滤，而不是退化为 self。

【Bug-6】P2 · 房源录入向导 Step2「下一步」按钮视觉缺失
- 位置：/house/wizard Step2
- 现象：选完小区后截图中只看到「上一步」，「下一步」按钮在视口外被遮挡
  （.wizard-actions 未吸底，长表单时需要滚动才能看到）。
- 建议：.wizard-actions 改为 sticky/fixed 底部悬浮，保证任意步骤都可见。
