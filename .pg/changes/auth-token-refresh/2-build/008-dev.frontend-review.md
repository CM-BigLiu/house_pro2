## FAIL 项详细

### R-3 — pattern_consistency（store 直接修改）

- **文件**: `code/web/src/utils/request.ts:73-74, 83-84`
- **问题**: 拦截器在 401 处理时直接对 Pinia store 的 state 赋值：
  ```typescript
  userStore.userInfo = null;
  userStore.menus = [];
  ```
  违反 vue3 `pattern_consistency` 的「store 直接修改」FAIL 判定：Pinia store state 未通过 action 修改（直接赋值）。
- **根因**: store 已有 `logout()` action 执行同等清理（`setTokens('','')` + `userInfo=null` + `menus=[]`），但 `logout` 现为 async 且会额外调用后端 logout API（refresh 失败场景下不希望再次触发后端登出），故拦截器未复用 `logout`，转而内联重复了清理逻辑并直接改 state。
- **建议**: 在 store 中抽取一个非网络独立的 action（如 `clearAuthState()`，仅清 accessToken/refreshToken/userInfo/menus），拦截器调用该 action，`logout` 内部也复用，消除直接 state 赋值。该问题不阻断本 track（score ≥ threshold 且非 P0），建议在 fix 阶段顺手修正。
