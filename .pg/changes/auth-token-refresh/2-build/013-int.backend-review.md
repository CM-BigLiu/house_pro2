int.backend 集成测试（`code/server/src/int/auth-token-refresh.int.spec.ts`）与 design.md 验证契约对齐：

| 契约（V-*） | 测试位置 | 状态 |

| V-backend-3 员工停用联动吊销 | `11.1-V3`（L275-290） | ✅ revokeUserTokens 后刷新 401 |
| V-backend-4 token_type 区分 | `11.1-V4`（L292-314） | ✅ refresh 不能当 access / access 不能调 refresh |
| V-fullstack-1 登录→刷新→登出全链路 | `11.1-FULL`（L316-354） | ✅ 全链路 + 登出后 refresh 401 |

补充说明（继承 dev.backend 审查结论，本次 diff 中 `code/server/src/modules/auth/**` 与 `code/server/src/common/guards/**` 的实现文件已在 dev.backend track 审查通过，未在本 track 变更）：
- `RefreshToken` entity 7 字段齐全（id/userId/tokenHash/status/expiresAt/createdAt/revokedAt），tokenHash unique + userId indexed，timestamptz 类型一致
- `AuthService.login/refresh/logout/revokeUserTokens` 齐全，refresh 返回 `{ accessToken }`（design 声明「可选轮换 refresh」，不返回新 refresh 属合规）
- design 提及「复用已有 sha256」，但 `crypto.util.ts` 实为 AES-GCM 字段加解密，无 sha256，dev 内置 `createHash('sha256')` helper 属正确必要实现，不构成 FAIL
