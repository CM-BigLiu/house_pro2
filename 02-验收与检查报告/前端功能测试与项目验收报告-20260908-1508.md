## 4. 缺陷清单

### P0-01 只读角色可进入写操作页面，租房写接口缺少操作权限约束

**现象**

1. `readonly` 无任何 action 权限，但租房房间仍显示“编辑/退租”。
2. `readonly` 可直接访问 `/house/rent/create`，看到完整新增表单和“保存”。
3. 首页仍向只读角色显示“录入租房/录入售房/录入储备”。

**代码证据**

- `code/web/src/views/house/RentView.vue:456-457`：房间“编辑/退租”未使用 `v-permission`。
- `code/web/src/views/dashboard/HomeView.vue:272-280`：录入快捷按钮未使用权限控制。
- `code/web/src/router/asyncRoutes.ts:18-21`：新增租房路由只校验菜单权限 `house:rent`，未校验 `renting:add`；同类隐藏新增路由普遍复用父菜单权限。
- `code/server/src/modules/house/controllers/rental.controller.ts:191-194`：新增租房接口没有 `@RequirePermission('renting:add')`。
- `code/server/src/common/guards/permission.guard.ts:21`：接口没有权限元数据时直接放行。
- `code/server/src/database/seeds/seed.service.ts:257`：`readonly` 的 action 权限确实为空。

**影响**

前端操作权限隔离失效，且租房新增接口存在实际越权写入风险，违反 U-004/U-005。该问题不仅是按钮显示问题，属于上线阻断。

**建议**

- 隐藏路由增加操作权限字段：新增用 `renting:add`、编辑用 `renting:edit`，其他模块同理。
- 所有写按钮补 `v-permission`，包括卡片内部房间操作和首页快捷入口。
- 后端所有写接口补 `@RequirePermission(...)`，并增加 `readonly` 返回 403 的接口 e2e。

### P0-02 首页使用静态 mock 数据，未按当前用户和权限渲染

**现象**

- `super_admin`、`agent02`、`readonly` 首页都显示同一用户“代建伟”和相同财务/房源/KPI 数据。
- 无财务菜单的 `agent02` 仍可看到财务到期预警、财务流水、押金和负债卡片。
- 页面显示 904 间有效房源等数据，与当前测试库中的 1 套租房、3 套售房不一致。

**代码证据**

- `code/web/src/views/dashboard/HomeView.vue:21-29` 明确声明并硬编码 Mock Data 与用户信息。
- `code/web/src/views/dashboard/HomeView.vue:37-248` 硬编码 KPI、预警、排行榜、房源、财务、待办等全部数据。
- `code/web/src/views/dashboard/HomeView.vue:254-255` 挂载后只延迟 300ms 关闭 loading，没有调用 dashboard API。

**影响**

违反首页数据准确性 H-008、角色差异 H-044，以及菜单/数据/操作权限统一性 U-003/U-004。管理决策页面展示虚假财务与经营数据，属于上线阻断。

**建议**

- 使用 `useUserStore().userInfo` 渲染当前用户。
- 接入现有 dashboard API，并按账号数据范围获取数据。
- 财务卡片、录入按钮、详情链接均按 action/menu 权限过滤。
- 增加 super_admin/agent02/readonly 三角色的首页快照与数据契约测试。

### P0-03 租房关键词筛选参数被后端忽略

**现象**

输入不存在关键词后列表仍返回原 1 套房源；售房页面同类查询正常。

**代码证据**

- `code/web/src/views/house/RentView.vue:15,39-44,297-307` 已绑定并发送 `keyword`。
- `code/web/src/api/rental.ts` 将查询对象作为参数发送到 `/house/rental-sets`。
- `code/server/src/modules/house/services/rental.service.ts:18-24` 只处理 `bizType` 和 `status`，未处理 `keyword`。

**影响**

违反 R-004/R-009，核心房源检索不可用。

**建议**

在 RentalService QueryBuilder 中对房源编码、小区名、地址、楼栋/单元/房号、房东/租客姓名及电话等字段增加参数化模糊查询，并补前后端契约测试。

### P1-01 用户信息与业务枚举未动态/中文化

- 首页用户卡固定为“代建伟”，与登录账号不一致。
- 租房房型、售房状态/标签直接显示英文代码，未按字典输出中文标签。
- 违反字典驱动与页面可读性要求。

### P1-02 首页工具栏与验收文档不完整

当前顶部仅有消息、通知和用户信息；H-002 要求的老板/我的展示、配置、收款码、钱包、首页设置、帮助、客服、城市切换等未完整实现。

### P2-01 地址单位重复

数据库名称已包含“号楼/单元”，页面再次拼接“栋/单元”，形成“1号楼栋2单元单元”。涉及 `RentView.vue:329` 与 `HouseWizardView.vue:81`。

### P2-02 前端自动化覆盖不足

前端共有 47 个动态路由记录，自动化测试仅 1 个文件、5 个认证用例；筛选、权限、动态菜单、表单校验、字典渲染和关键业务流程均无回归保护。

## 6. 验收结论与放行条件

### 6.1 当前结论

**不通过，不建议上线。**

虽然登录、动态菜单、核心页面渲染、售房数据范围、四步向导、级联、必填校验、黑名单预警和全部工程门禁均通过，但权限越权、首页虚假/越权数据、租房核心检索失效均属于 P0，达到仓库验收规则中的驳回条件。

### 6.2 重新验收前必须完成

1. 修复 P0-01：前端路由/按钮与后端写接口全部补操作权限，`readonly` 写请求必须返回 403。
2. 修复 P0-02：首页接真实接口、真实用户，并按角色/数据范围隐藏不应展示的卡片和入口。
3. 修复 P0-03：租房关键词查询后端实现并补自动化测试。
4. 对所有隐藏新增/编辑路由做一次 action permission 横向审计，不能只修租房模块。
5. 增加至少一组多角色浏览器回归：`super_admin`、`agent02`、`readonly`。

P1/P2 可在 P0 修复后同轮处理；P3 工程警告不阻断，但建议在依赖升级前清理。
