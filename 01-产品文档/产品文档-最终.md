## 1. 文档概述

### 1.1 系统定位

本系统为面向 **房屋租售一体化运营** 的 ERP 管理平台，覆盖：
- **租售房源全生命周期**：储备房源 → 拿房签约 → 租房/售房管理 → 退租/成交 → 归档
- **客源全生命周期**：储备客源 → 跟进 → 转签约 → 成交
- **财务全链路**：账单 → 流水 → 利润核算 → 业绩分配 → 开票
- **系统配置中心**：角色权限、字典、人员、模板

### 1.2 设计原则

1. **权限到店**：所有操作权限细化到「店面」级别，支持「我的 / 本店 / 全部分店」三级数据范围。
2. **字段驱动**：所有业务模块的可选项通过字典维护，业务模块不改代码即可新增枚举值。
3. **模板化**：合同、短信、微信菜单通过模板配置生效。
4. **审计透明**：所有设置变更写入操作日志，可追溯到人、时间、IP。
5. **多端一致**：PC Web、桌面客户端、移动 APP 三端共享同一套权限与字典。
6. **卡片优先**：所有房源/客源列表默认采用 card 卡片视图，支持「删图模式」加速渲染。

### 1.3 一级菜单结构

| 一级菜单 | 二级菜单 | 说明 |
|---|---|---|
| **首页** | — | 看板（工作台） |
| **房屋管理** | 租房管理、退租管理、押金管理、售房管理、储备房源、储备客源、客户管理、黑名单、小区管理 | 房源 + 客源 + 退租押金 + 小区；退租/押金紧跟租房，贴合「租前 → 退租 → 押金清算」业务动线 |
| **财务管理** | 账单、流水账、涨价统计、公寓利润、合伙人、收入成本、业绩核算、财务核算、欠款统计、收支计划、代付管理、开票管理 | 12 个财务子模块 |
| **系统管理** | 角色管理、权限管理、字典管理、人员管理 | 系统配置 |

## 2. 统一角色与权限模型

> 本节为整合三个文档后的统一 RBAC 模型，基于「角色 + 数据范围 + 权限点」三元模型。

### 2.1 核心实体关系

```
公司 (Company)
  │
  ├── 城市 (City)                          地理维度
  │     │
  │     ├── 店面 (Store)                  业务单元
  │     │     │
  │     │     ├── 分组 (Group)            1组 / 2组 / 转移1 / 转移2
  │     │     │
  │     │     └── 部门 (Department)       业务部 / 财务部 / 销售部…
  │     │           │
  │     │           └── 员工 (Employee)   实际使用者
  │     │                 │
  │     │                 ├── 职位 (Position)        多职位绑定
  │     │                 └── 角色 (Role)            多角色绑定
  │     │
  │     └── 角色 (Role)                    跨店面复用
  │           │
  │           └── 权限集 (Permission)     菜单 + 按钮 + 数据范围
  │
  └── 字典 (Dictionary)                   独立组织
        └── 字典项 (DictItem)             业务枚举值
```

### 2.2 角色体系

| 角色代码 | 角色名 | 默认数据范围 | 默认菜单权限 | 备注 |
|---|---|---|---|---|
| `super_admin` | 超级管理员 | 全部 | 全部菜单 + 系统管理 | 系统初始化唯一账号 |
| `company_admin` | 公司管理员 | 全部 | 全部业务模块（不含系统管理） | 公司内最高管理岗 |
| `store_manager` | 店长 | 本店 + 跨店授权 | 业务模块 + 店内权限 | 一店一个或多个 |
| `finance_manager` | 财务负责人 | 全部（财务） | 财务管理模块 + 财务核算 | 跨店面财务 |
| `finance_clerk` | 财务专员 | 本店 | 流水账 / 账单 / 发票管理 | |
| `housekeeper_lead` | 管家组长 | 本组 | 房源 / 租客 / 合同 | |
| `housekeeper` | 管家 | 本组（本人） | 房源 / 租客 / 合同（受限） | |
| `salesman` | 业务员 | 本店（本人） | 房源 / 客源 / 储备房源 / 储备客源 | 录入与跟进 |
| `agent` | 综合经纪人 | 本店（本人） | 租售房源录入 / 维护 / 跟进 | 适用于售房业务 |
| `maintenance` | 维修工 | 本店 | 维修工单 / 巡房 | |
| `auditor` | 审批人 | 全部（仅审批） | 审批中心 | 通常兼任店长 |
| `readonly` | 只读账号 | 按授权 | 仅查看，无任何操作 | 给老板 / 审计 |

> 角色可扩展，每个公司可基于基础角色自定义。角色支持 **父子继承**：子角色自动继承父角色的全部权限。

### 2.3 数据范围（Data Scope）

| 范围代码 | 范围名 | 含义 | 适用场景 |
|---|---|---|---|
| `self` | 仅自己 | 只看自己录入 / 维护的数据 | 业务员 / 管家 / 综合经纪人 |
| `group` | 本组 | 看本分组所有员工数据 | 管家组长 |
| `store` | 本店 | 看本店所有数据 | 店长 / 财务专员 |
| `company` | 全公司 | 看公司全部数据 | 公司管理员 |
| `assigned` | 指定店面 | 由管理员手动指定可看的店面列表 | 跨店支援 |
| `custom` | 自定义 | 自定义条件（DSL 表达式） | 高级配置 |

### 2.4 权限点

权限点分为三级：

```
权限点
├── 菜单权限 (menu)        控制模块的可见性
├── 操作权限 (action)      控制模块内按钮（新增 / 修改 / 删除 / 导出 / 审核…）
└── 数据权限 (data)        控制数据范围（见 2.3）
```

### 2.5 角色与员工的绑定

- 一个员工可绑定 **多个角色**（角色集合权限取并集）；
- 一个员工可拥有 **多职位**（业务部经理 + 财务专员），职位决定默认角色与门店；
- 角色绑定菜单 / 操作权限；数据范围由员工属性（所属店面 / 分组）+ 角色覆盖；
- 员工可拥有「额外授权」（temporaryAuth）：临时授予某权限，过期自动失效。

### 5.7 退租管理

> 路由：`/house/checkout` · 权限 `house:checkout` · 菜单位置：房屋管理 → 退租管理（第 2 项，紧跟租房管理）
> 租客退租的 **登记、审核确认、费用清算** 全流程管理中心。退租申请由租房管理卡片页发起，在此完成审批闭环。

#### 5.7.1 退租业务全流程

```
┌──────────────── 租房管理（卡片页）────────────────┐
│  整租卡片「退租」按钮        合租房间「退租」按钮  │
└──────────────┬──────────────────┬────────────────┘
               │ ①退房登记（前端校验+确认弹框）
               ▼
        [合租校验] 仍租期内租客 → 阻止整房退租
               │ 通过
               ▼
     ② POST /api/house/checkouts ──► 生成退租记录
        （自动编号 CK-YYYYMMDD-NNN，状态 pending 待确认）
               │
               ▼
┌──────────────── 退租管理（本页）──────────────────┐
│  ③ 状态 Tab 筛选「待确认」→ 定位新记录            │
│  ④ 核对房源/租客/退租日期/费用清算/原因           │
│  ⑤ 点「确认」→ 二次确认弹框                       │
│     POST /api/house/checkouts/:id/confirm         │
│     pending ──► confirmed（已确认）                │
│  ⑥ 后续：费用清算划付 + 押金退还 → completed      │
└───────────────────────────────────────────────────┘
               │
               ▼
        ⑦ 联动：押金管理生成退款事项（见 5.8）
```

**状态机**：`pending`（待确认）→ `confirmed`（已确认）→ `completed`（已完成，清算与押金处理完毕）

    ↓
[收 / 付]  →  实收 / 实付  →  终审  →  出纳
    ↓                              ↓
[已收 / 已付]                      [未出纳财务] → [已出纳]
    ↓
[超期未付]  →  逾期
    ↓
[冲红 / 退账]  →  冲红流水
```

#### 6.13.2 利润核算（权责发生制）

```
合同开始
    ↓
按月分摊（计租天数 / 应收付日）
    ↓
[收入] 租金收入 + 其他收入
[成本] 租金成本 + 其他成本
    ↓
毛利 = 收入 - 成本
    ↓
毛利率 = 毛利 / 收入 × 100%
    ↓
公寓利润表（汇总）→ 系统外挂入（补充项）→ 最终利润
```

#### 6.13.3 业绩分配流程

```
[房源签约] → 房源产生业绩
    ↓
[管家 / 收房业务员 / 出房业务员] 按规则分成
    ↓
[房源总业绩] = 已分配业绩 + 留存转移 + 留存业绩
    ↓
[业绩偏好设置] 控制分配规则
    ↓
[员工业绩报表] → 工资核算
```

# 语法（参考 SQL WHERE）
{
  "logic": "AND",

      { "field": "status", "op": "in", "value": ["vacant", "reserved", "rented", "collected"] }
    ]}
  ]
}
```

操作符支持：`=, !=, in, not in, >, <, between, like, is null, is not null`

## 10. 业务流程

### 10.1 房源全生命周期

```
[业主委托]
   ↓
[经纪人预录入] ─── 我的预录入房源
   ↓
[正式录入 / 楼盘选择 → 基本信息 → 特色信息 → 完成]
   ↓
[验真] (可选)
   ↓
[上架 / 加入全城联卖] ─── 售房房源 / 租房房源
   ↓
[议价 / 调价]
   ↓
[带看 / 客户匹配] ─── 与「客户管理」联动
   ↓
[签约] ─── 成交房源
   ↓
[下架 / 归档]
```

### 10.2 储备房源 → 租房/售房管理 流转

```
[储备房源 录入]
   ↓ 跟进
[拿房签约] ─── 签房东合同 ─── 进入租房管理（整租/合租）
   ↓ 自动流转
[租房管理] ── 房间登记到房间卡片
   ↓
[租客交定] ─── 房间状态变为「已定」
   ↓
[租客签约] ─── 房间状态变为「已租」 ── 自动生成账单
   ↓
[退房] ─── 房间状态变为「退」 ─── 进入退房审批 ─── 退回「未租」
   ↓
[配置 / 脏房 / 维修] ── 装修或保洁流程 ── 重新可租
```

### 10.3 客源全生命周期

```
[储备客源 录入求租]
   ↓ 跟进 / 带看
[客户状态流转]：未租 → 电话未接听 / 暂不租 / 已定
   ↓
[转到整租 / 转到合租] ── 跨模块流转到对应房间管理
   ↓
[租客签约] ── 客户状态变为「已租」
```

### 10.4 跟进 SLA

- 系统提示"X 天未跟进"，触发跟进按钮
- 房源质量分与跟进频率强相关（每日跟进 → 高分；久未跟进 → 降级）

### 10.5 验真 / 速销流程

- 政府核验码录入 → 提交官方核验 → 验真状态变更
- 速销：与业主签订速销协议，设定速销起始 / 截止日期；到期自动转议价或下架

### 10.6 黑名单命中流程

```
录入租客签约 / 添加房东
   ↓ 输入手机号 / 身份证
   ↓ 实时校验黑名单
命中
   ↓ 弹窗显示「命中黑名单，原因：xxx」
   ├── 强拦截（不允许继续）
   └── 解除黑名单 / 修改手机号 / 走特批流程
未命中
   ↓ 继续业务
```

### 10.7 角色授权流程

```
超级管理员
   ↓ 新建角色 + 配置权限
角色定义完成
   ↓ 为员工绑定角色（多选）
员工权限生效
   ↓ 员工登录 → 验证菜单权限 + 操作权限 + 数据范围
按权限访问
   ↓ 离职 / 转岗 → 角色变更 / 解除绑定
权限回收
```

| 维度 | 要求 |

## 13. 已知体验细节

1. **登录后首屏弹窗**：「我的待办」对话框默认弹出，显示审批流程、巡房逾期提醒、在线反馈等待办项，需逐条处理后才能关闭；右上角「首页设置」可配置不自动弹出。
2. **网易易盾滑动验证**：登录后首次访问触发，新会话需过滑块验证。
3. **排序字段下拉**：使用 `el-dropdown-menu`，支持升降序切换。
4. **多 tab 视图**（售房/成交/我的/预录入/收藏）共用同一份 API 但通过 `dataRange` 过滤。
5. **卡片视图是默认**；图片可一键隐藏（删图模式）以提升渲染速度。
6. **卡片右上操作区**按权限动态展示（维护人 vs 非维护人看到的按钮不同）。
7. **角色复制**：「店长」等通用角色支持一键复制为「副店长」或「店长-华东大区」，快速复用权限配置。
8. **权限预览**：新建角色时可在「权限预览」标签实时预览该角色的可见菜单和操作按钮。
9. **黑名单多维校验**：录入租客时同时校验手机号 + 身份证 + 姓名（模糊匹配），避免「换号逃黑」。
10. **操作日志脱敏**：身份证 / 银行卡 / 密码等敏感字段在操作日志中显示为 `****`，需要「申请脱敏查看」权限。
11. **看板拖拽排版**：grid-stack 拖拽变更后实时保存到后端，刷新后保持。
12. **老板视图**：老板可见老板专属视图（包含未公开老板视图），其他角色看不到。
13. **看板复制链接**：每张卡片右上角可复制「带筛选条件的 URL」，发给同事直接定位数据。
14. **权责发生制**：公寓利润与收入成本模块基于权责发生制（按月分摊计租天数），而非现金收付；与「流水账」现金收付形成对比。
15. **业绩偏好设置**：业绩核算模块支持「业绩偏好设置」自定义分配规则（管家 / 收房 / 出房 / 中介的多方分成比例）。
16. **开票申请流程**：开票管理支持租客发票 / 房东发票 / 公司主动申请三类来源，状态经历 待处理 → 开票中 → 已开票，已开票可作废（已冲红）。

### C.2 整合要点

1. **角色、授权统一**：基于 03 文档的 RBAC 模型（角色 + 数据范围 + 权限点），合并 01/02 文档的角色定义，新增 `agent`（综合经纪人）角色适配售房业务。
2. **租售房录入流程风格统一**：租房 / 售房 / 储备房源的录入向导统一为 4 步（楼盘选择 → 基本信息 → 特色信息 → 完成），通过 `transType` 参数区分必填字段集合。
3. **房源列表统一 card 显示**：租房、售房、储备房源、储备客源、客户管理的列表全部采用卡片视图，支持「删图模式」。
4. **看板功能整合为一个**：合并 01 文档第 13 章（优居首页看板：用户卡片 + 数据概览 + 待办审批 + 系统公告 + 业绩排行榜）和 03 文档第 21 章（全房通首页看板：12 张小卡片 + 18 张大卡片），形成统一的首页看板。
5. **菜单结构精简**：从原三文档的 30+ 菜单精简为四大一级菜单（首页、房屋管理、财务管理、系统管理），共 23 个二级菜单。
6. **财务管理精简**：原 02 文档的 16 个财务子模块整合为 12 个（剔除 legacy 兼容页 `daily-account-legacy` / `old-embedded-new-debts` + 入口按钮 `book-keeping` / `batch-review`）。
7. **系统管理精简**：原 03 文档的 12 个系统设置子模块整合为 4 个（角色管理、权限管理、字典管理、人员管理），其中「人员管理」合并了原「店面设置 + 员工与部门」。
8. **保留的关键功能**：
   - 售房：4 步录入向导、28 个标签、智能标题、业主校验、验真、速销、议价、全城联卖、租售同存
   - 租房：整租/合租两层结构、套利润、房型、房间状态、批量操作、视图管理
   - 储备：拿房签约、私盘转公盘、短信房东、跨模块流转
   - 财务：账单全生命周期、权责发生制利润核算、业绩分配、代付、开票
   - 系统：RBAC + 角色继承、数据范围 DSL、字典驱动、操作日志审计、黑名单联动
