## 1. 文档概述

### 1.1 模块定位
系统设置是整个 ERP 的 **配置中心 + 权限中心 + 数据中心**，承担：
- **组织架构管理**：城市 / 店面 / 分组 / 部门 / 员工
- **权限与角色**：基于 RBAC（角色访问控制）+ 数据范围（店面级）的精细化授权
- **业务字典**：可枚举字段的统一维护（房源类型、客户来源、缴费方式…）
- **模板与流程**：合同电子模板、短信模板、微信菜单模板
- **支付与税务**：微信支付、钱包、分账、开票主体
- **数据治理**：回收站、黑名单、操作日志

### 1.2 设计原则
1. **权限到店**：所有操作权限都细化到「店面」级别，支持「我的 / 本店 / 全部分店」三级数据范围。
2. **字段驱动**：所有业务模块的可选项（房源类型、客户来源、装修情况等）都通过字典维护，业务模块不改代码即可新增枚举值。
3. **模板化**：合同、短信、微信菜单都通过模板配置生效，无需发布。
4. **审计透明**：所有设置变更写入操作日志，可追溯到人、时间、IP。
5. **多端一致**：PC Web、桌面客户端、移动 APP 三端共享同一套权限与字典。

### 1.3 一级菜单与子模块
系统设置位于一级菜单，含 12 个子模块：

| 子模块 | 路由 | 渲染方式 | 业务定位 |
|---|---|---|---|
| **店面设置** | `/system-settings/store` | iframe | 城市 / 店面 / 分组的组织架构 |
| **员工与部门** | `/system-settings/employee` | SPA | 员工 / 部门 CRUD |
| **权限与角色** | `/system-settings/permission` | SPA | 角色 + 数据范围 + 按钮权限 |
| **字典设置** | `/system-settings/dictionary` | iframe | 业务字段枚举维护 |
| **合同模板** | `/system-settings/contract-template` | SPA | 标准/非标准电子合同模板 |
| **富文本合同** | `/system-settings/contract-rich` | SPA | 在线合同富文本编辑器 |
| **短信模板** | `/system-settings/sms` | SPA | 短信模板与触发规则 |
| **微信设置** | `/system-settings/wechat` | SPA | 租客/房东端小程序与公众号配置 |

## 2. 角色与权限模型

> 本节为本模块的核心，基于全房通「员工授权」的「部门 + 职位 + 数据范围 + 按钮权限」四元模型重构。

### 2.1 核心实体关系

```
公司 (Company)
  │
  ├── 城市 (City)                          地理维度
  │     │
  │     ├── 店面 (Store)                  业务单元
  │     │     │
  │     │     ├── 分组 (Group)            1组 / 2组 / 转移1 / 转移2
  │     │     │
  │     │     └── 部门 (Department)       业务部 / 财务部 / 销售部…
  │     │           │
  │     │           └── 员工 (Employee)   实际使用者
  │     │                 │
  │     │                 ├── 职位 (Position)        多职位绑定
  │     │                 └── 角色 (Role)            多角色绑定
  │     │
  │     └── 角色 (Role)                    跨店面复用
  │           │
  │           └── 权限集 (Permission)     菜单 + 按钮 + 数据范围
  │
  └── 字典 (Dictionary)                   独立组织
        └── 字典项 (DictItem)             业务枚举值
```

### 2.2 角色体系（参考全房通「管理员/店长/业务员」三级）

| 角色代码 | 角色名 | 默认数据范围 | 默认菜单权限 | 备注 |
|---|---|---|---|---|
| `super_admin` | 超级管理员 | 全部 | 全部菜单 + 系统设置 | 系统初始化唯一账号 |
| `company_admin` | 公司管理员 | 全部 | 全部业务模块（不含系统设置） | 公司内最高管理岗 |
| `store_manager` | 店长 | 本店 + 跨店授权 | 业务模块 + 店内权限 | 一店一个或多个 |
| `finance_manager` | 财务负责人 | 全部（财务） | 财务管理模块 + 财务核算 | 跨店面财务 |
| `finance_clerk` | 财务专员 | 本店 | 流水账 / 账单 / 发票管理 | |
| `housekeeper_lead` | 管家组长 | 本组 | 房源 / 租客 / 合同 | |
| `housekeeper` | 管家 | 本组（本人） | 房源 / 租客 / 合同（受限） | |
| `salesman` | 业务员 | 本店（本人） | 房源 / 客源 / 储备房源 / 储备客源 | 录入与跟进 |
| `maintenance` | 维修工 | 本店 | 维修工单 / 巡房 | |
| `cleaner` | 保洁员 | 本店 | 保洁工单 / 巡房 | |
| `auditor` | 审批人 | 全部（仅审批） | 审批中心 | 通常兼任店长 |
| `readonly` | 只读账号 | 按授权 | 仅查看，无任何操作 | 给老板 / 审计 |

> 角色可扩展，每个公司可基于基础角色自定义。

### 2.3 数据范围（Data Scope）

| 范围代码 | 范围名 | 含义 | 适用场景 |
|---|---|---|---|
| `self` | 仅自己 | 只看自己录入 / 维护的数据 | 业务员 / 管家 |
| `group` | 本组 | 看本分组所有员工数据 | 管家组长 |
| `store` | 本店 | 看本店所有数据 | 店长 / 财务专员 |
| `company` | 全公司 | 看公司全部数据 | 公司管理员 |
| `assigned` | 指定店面 | 由管理员手动指定可看的店面列表 | 跨店支援 |
| `custom` | 自定义 | 自定义条件（如「可看管家为本人的所有房源」） | 高级配置 |

> 与全房通对比：全房通的数据范围是硬编码的字符串（"查看全部"/"【可看勾选店面所有房源】北京市：总部店(1组,2组)"）；本设计抽象为枚举 + 灵活的可选配置（assigned + custom）。

### 2.4 权限点（Permission）

权限点分为三级：

```
权限点
├── 菜单权限 (menu)        控制模块的可见性
├── 操作权限 (action)      控制模块内按钮（新增 / 修改 / 删除 / 导出 / 审核…）
└── 数据权限 (data)        控制数据范围（见 2.3）
```

### 2.5 角色与员工的绑定

- 一个员工可绑定 **多个角色**（角色集合权限取并集）；
- 一个员工可拥有 **多职位**（业务部经理 + 财务专员），职位决定默认角色与门店；
- 角色绑定菜单 / 操作权限；数据范围由员工属性（所属店面 / 分组）+ 角色覆盖；
- 员工可拥有「额外授权」（temporaryAuth）：临时授予某权限，过期自动失效。

- **转组**：把店面下整租房源 / 合租房源 / 集中房源 / 全部房源批量转到另一店面

- **编辑**：修改店面信息
- **删除**：软删除到回收站

### 5.3 角色继承
- 角色支持 **父子继承**：子角色自动继承父角色的全部权限；

### 5.4 自定义范围表达式（custom scope）

参考全房通的「可看管家为本人的所有房源，也可看管家为他人的「未租房间」「本人已定」「本人已租」「本人已收」「他人待退」「他人待转」「他人待换」「房间已冻结（未租）」」场景，本设计抽象为 **DSL 表达式**：

```
# 语法（参考 SQL WHERE）
{
  "logic": "AND",
  "conditions": [
    { "field": "housekeeper_id", "op": "=", "value": "${self.id}" },
    { "logic": "OR", "conditions": [
      { "field": "status", "op": "in", "value": ["vacant", "reserved", "rented", "collected"] }
    ]}
  ]
}
```

操作符支持：`=, !=, in, not in, >, <, between, like, is null, is not null`

### 5.5 数据权限独立配置

每个模块可单独覆盖数据范围。例如：「房源模块」按 `company` 全可见，但「财务报表」按 `store` 仅本店可见。

| 模块 | 默认范围 | 可覆盖为 |
|---|---|---|
| 整租 / 合租 / 集中 | self | group / store / company / assigned |
| 储备房源 | self | group / store / company / assigned |
| 储备客源 | self | group / store / company / assigned |
| 账单 / 流水账 | store | company / assigned |
| 公寓利润 | store | company |
| 业绩核算 | group | store / company |
| 系统设置 | 仅超管 | - |

### 5.6 待分配员工

新员工通过二维码邀请但未被管理员审核的，进入「待分配员工」列表，管理员可：
- 查看邀请详情（邀请人、邀请时间、扫码端、IP）
- 编辑资料 → 通过审核 → 进入员工列表
- 拒绝：删除邀请记录

## 16. 业务流程

### 16.1 角色授权流程
```
超级管理员
   ↓ 新建角色 + 配置权限
角色定义完成
   ↓ 为员工绑定角色（多选）
员工权限生效
   ↓ 员工登录 → 验证菜单权限 + 操作权限 + 数据范围
按权限访问
   ↓ 离职 / 转岗 → 角色变更 / 解除绑定
权限回收
```

### 16.2 员工邀请流程
```
管理员 [生成二维码] → 二维码链接（含邀请码 + 邀请人）
   ↓
员工扫码 → 填写手机号 + 姓名 + 邀请码 → 提交
   ↓
进入「待分配员工」→ 管理员审核
   ├── 通过 → 补充资料 + 分配角色 → 进入员工列表
   └── 拒绝 → 记录拒绝原因 → 员工收到通知
```

### 16.3 黑名单命中流程
```
录入租客签约 / 添加房东
   ↓ 输入手机号 / 身份证
   ↓ 实时校验黑名单
命中
   ↓ 弹窗显示「命中黑名单，原因：xxx」
   ├── 强拦截（不允许继续）
   └── 解除黑名单 / 修改手机号 / 走特批流程
未命中
   ↓ 继续业务
```

### 16.4 数据修改审计流程
```
任何配置变更（员工 / 角色 / 字典 / 模板 / 支付）
   ↓
自动写入 AuditLog
   ↓
变更前快照 + 变更后快照 + 变更字段差异
   ↓
敏感操作（角色权限变更 / 删除数据）实时通知超管
   ↓
保留 180 天（热数据）+ 3 年（冷归档）
```

## 19. 已知体验细节

1. **角色复制**：「店长」等通用角色支持一键复制为「副店长」或「店长-华东大区」，快速复用权限配置。
2. **权限预览**：新建角色时可在「权限预览」标签实时预览该角色的可见菜单和操作按钮。
3. **微信菜单拖动**：小程序首页 / 公众号首页的菜单顺序通过「拖动排序」配置，无需开发介入。
4. **短信模板还原**：修改系统预设模板后，「还原」按钮可恢复到默认内容，保留用户数据。
5. **回收站联动删除**：关联数据存在时（如房间被合同引用），回收站支持「查看关联数据」并强制级联删除。
6. **黑名单多维校验**：录入租客时同时校验手机号 + 身份证 + 姓名（模糊匹配），避免「换号逃黑」。
7. **操作日志脱敏**：身份证 / 银行卡 / 密码等敏感字段在操作日志中显示为 `****`，需要「申请脱敏查看」权限。

## 20. 待确认事项（产品侧）

1. 角色继承最多支持几层？建议 3 层（公司 > 业务线 > 岗位）。
2. 数据范围「custom」是否对超管开放编辑？建议开放但需审批。
3. 短信模板的「模拟发送」是否计费？建议按真实短信费扣减，预留充值入口。
4. 微信小程序是否需要支持「多端」（同时支持 微信小程序 + 支付宝小程序 + 抖音小程序）？
5. 黑名单生效范围是否支持「指定门店 + 时间段」组合？例如「在 A 店 2026-01-01 之前有效」。
6. 操作日志的「before / after 快照」对超大对象（如房源图片列表）如何处理？建议只保留关键字段。
7. 是否需要支持「权限继承自 OA 系统」或「SSO 单点登录」？
8. 支付分账是否需要对接多家支付平台（微信 / 支付宝 / 银联 / 通联）？

6. **复制链接**：每张卡片右上角可复制「带筛选条件的 URL」，发给同事直接定位数据。

## 附录 E：抓取参考说明

本次文档以全房通 VIP 系统（`https://quanfangtongvip.com/`）10 个系统设置子模块为参考基础，结合本项目（house_pro4，住宅租赁业务）的实际场景进行重构和扩展。参考账号：赵波 / 15003341128。

**主要采集路由**：
- `/system-settings/store-front` - 店面设置（iframe `/web/store/storeList?`）
- `/system-settings/permission` - 员工授权（5 个 Tab：员工/部门、职位/权限、待分配员工、核心字段设置、人脸识别设置、操作日志）
- `/system-settings/dictionary` - 字典设置（iframe `/web/dic/list?` + `/web/property/getAreaPropertyPage`）
- `/system-settings/contract` - 合同设置（电子合同模板 + 纸质合同模板 + 电子定金模板）
- `/system-settings/short-message` - 短信设置（49+ 内置模板）
- `/system-settings/we-chat` - 微信设置（11 个分组）
- `/system-settings/payment` - 支付设置（商户绑定 + 钱包 + 分账）
- `/system-settings/recycle-bin` - 回收站（10 个 Tab）
- `/system-settings/tenant-blacklist` - 黑名单（联动校验）
- `/system-settings/richtext-contract` - 富文本电子合同（独立模块）

**全房通关键观察**：
- 角色以「职位 + 数据范围字符串」硬编码（如「查看全部」「【可看勾选店面所有房源】北京市：总部店(1组,2组)」）；
- 权限粒度停留在「菜单 + 按钮」，缺少细粒度的字段权限；
- 短信模板丰富但缺少「定时发送」「条件触发」能力；
- 回收站聚合了 10 个 Tab 但缺少「彻底删除」的权限隔离；
- 黑名单只有列表管理，缺少主动校验与流程联动。

**本系统的改进**：
- 抽象出「数据范围 = 枚举 + 自定义 DSL」，支持自定义表达式；
- 引入「RBAC 角色 + 角色继承 + 细粒度权限点」模型；
- 短信模板支持「定时发送」与「触发器配置」；
- 回收站「彻底删除」需走「二次确认 + 审批」流程；
- 黑名单多维校验（手机 + 身份证 + 姓名模糊匹配）；
- 新增「操作日志」独立模块，含监控告警与快照对比；
- 新增「核心字段设置」与「人脸识别设置」子模块。
